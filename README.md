1. Функционалности
Управление на проекти
 Позволява създаване, редактиране и изтриване на проекти, които съдържат множество задачи.
Управление на задачи
 Към всеки проект могат да се добавят задачи с име, описание и краен срок.
Статус на задачите
 Всяка задача има статус (TODO, IN_PROGRESS, DONE), който може да се променя.
Приоритет на задачите
 Задачите се класифицират по приоритет (LOW, MEDIUM, HIGH).
Филтриране на задачи
 Потребителят може да извежда задачи по статус, приоритет или проект.
Сортиране на задачи
 Задачите могат да се подреждат по краен срок или приоритет.
Проследяване на крайни срокове
 Системата показва кои задачи са закъснели или предстоят скоро.
Назначаване на потребител към задача
 Всяка задача може да бъде възложена на конкретен потребител.
История на действията
 Записват се всички промени по задачите (създаване, редакция, промяна на статус).

2. Клас диаграма (описание)
User (Потребител)
id : int (private)
name : string (private)
email : string (private)

Task (Задача)
id : int (private)
title : string (private)
description : string (private)
deadline : string (private)
priority : Priority (private)
status : Status (private)
assignedUser : указател към User (private)

Project (Проект)
id : int (private)
name : string (private)
description : string (private)
tasks : динамичен списък от Task (private, реализиран чрез vector)

ActivityLog (История)
id : int (private)
action : string (private)
date : string (private)
task : указател към Task (private)

Priority (изброим тип)
LOW
MEDIUM
HIGH

Status (изброим тип)
TODO
IN_PROGRESS
DONE

Връзки между класовете
Един проект съдържа множество задачи (1 към много)
Всяка задача принадлежи на точно един проект
Всяка задача може да има един потребител
Всяка задача може да има множество записи в историята
Историята е свързана с конкретна задача чрез указател

3. Обосновка на дизайн решения
Използване на изброими типове (enum)
 Priority и Status са реализирани като изброими типове, защото имат ограничен брой стойности. Това намалява грешки и улеснява работата с тях.
Капсулация чрез private полета
 Всички полета са private, за да се защити вътрешното състояние на обектите. Достъпът до тях става чрез публични методи.
Използване на динамичен списък (vector)
 Задачите в проекта се съхраняват в динамична структура, което позволява лесно добавяне и премахване.
Използване на указатели за връзки между обекти
 Вместо копиране на цели обекти се използват указатели (например към User и Task), което е по-ефективно и типично за C++.
